# panel — нативная панель macOS

Четыре вопроса закрыты: **окно ведёт себя как требует макет** (этап UI-1), **выдача приходит
из шва, а не прибита к экрану** (этап UI-2), **панель ищет в настоящих контекстах** (этап UI-3)
и **⇥ показывает, как строка связана с остальным графом** (этап UI-4).

Ядра Rust здесь нет ни в одной строке. Выдача приходит за протоколом `ResultFeed`: по
умолчанию — из ядра, процессом `crosskit … search --json` на каждую страницу; ключом
`--state` — из выдуманного источника. Граница приложений по
[ADR 0032](../../docs/adr/0032-three-applications-and-one-boundary.md) — демон; до него панель
ходит через CLI, и почему этого пока достаточно — [ADR 0044](../../docs/adr/0044-the-panel-reaches-the-core-through-a-process-for-now.md).

## Сборка и запуск

Сборка из терминала, без открытия Xcode:

```
xcodebuild -project apps/panel/CrosskitPanel.xcodeproj -scheme CrosskitPanel build
```

Запуск — из каталога сборки, который назовёт сам `xcodebuild`:

```
APP=$(xcodebuild -project apps/panel/CrosskitPanel.xcodeproj -scheme CrosskitPanel \
      -showBuildSettings | awk -F' = ' '/ BUILT_PRODUCTS_DIR /{print $2}' | head -1)
"$APP/CrosskitPanel.app/Contents/MacOS/CrosskitPanel"
```

Запускать лучше так, а не через `open`: приложение пишет в stdout протокол поведения окна,
замеры и то, что сделала бы каждая клавиша. Через `open` этого не видно.

### На настоящих данных

Панель не открывает базу и не читает `config.toml` сама — всё через `crosskit`. Где он лежит,
панель узнаёт из ключа `--core=<путь>`, иначе ищет `crosskit` в `PATH`. Обёртка-функция
оболочки в `PATH` не видна, поэтому надёжнее собрать ядро и назвать файл:

```
cargo build --release
"$APP/CrosskitPanel.app/Contents/MacOS/CrosskitPanel" --core="$PWD/target/release/crosskit"
```

Команда запускается из корня репозитория. Контексты панель берёт из `crosskit contexts
--json` при старте, начинает с первого (`--context=<имя>` — с названного), ⌘K переключает.
Переменные `CROSSKIT_DATA_DIR` и `CROSSKIT_CONFIG`, если они заданы, процесс ядра наследует
от панели.

⌥Space показывает и прячет панель, esc прячет, ⌘Q завершает.

### Ключи запуска

Ключи `--state` нужны для одного: снять снимок каждого состояния, не подделывая данные.
Состояние — это начальные условия, а не заранее нарисованный экран: дальше панель ведёт себя
обычно.

| ключ | что делает |
| --- | --- |
| `--feed=core` | источник — ядро; умолчание, если `--state` не назван |
| `--feed=invented` | источник — выдуманный корпус; умолчание, если `--state` назван |
| `--core=<путь>` | исполняемый файл `crosskit`; без ключа — первый `crosskit` в `PATH` |
| `--replay=<файл>` | замер моста: запросы из файла по одному, числа в stdout, выход (раздел «Замер») |
| `--graph-replay=<файл>` | замер графа: `<глубина> <фокус>` на строку, числа в stdout, выход |
| `--graph-focus=<фокус>` | показать панель и сразу граф этого фокуса |
| `--snapshot=<файл>` | с `--graph-focus` или `--knowledge`: снимок окна в PNG, когда граф или карта нарисованы, затем выход |
| `--knowledge` | показать панель и сразу карту знаний контекста; печатает время ядра и раскладки |
| `--pick=<id>` | с `--knowledge`: выбрать сущность или связь, когда карта разложена, — карточку связи иначе не снять без клика |
| `--probe-gestures` | с `--knowledge` или `--graph-focus`: две пальца, колесо с ⌃, стрелки (и с ⇧, и удержание), + = − 0, кнопка «+», ⏎, ⌥↓ ⌥↓, ⏎ по шагам, синтезом **окну** (`sendEvent`) — тем путём, каким приложение отдаёт настоящие; печатает зум и сдвиг на каждом шаге и что стало со строкой запроса. ⏎ только печатает, что открыл бы. Окно на экране, но клавиатуру не берёт: чужие буквы не попадают в замер |
| `--appearance=dark\|light` | оформление вместо системного — снять обе темы |
| `--state=main` | запрос «маркер политика» — выдача с выделенной строкой |
| `--state=empty` | пустой запрос — недавние беседы, подсказки, состав контекста |
| `--state=typing` | запрос «идемпо» и источник, который «думает» 4 с: допечатайте букву и увидите выдачу, помеченную «обновляется» |
| `--state=noresults` | пустой источник: «ничего нет» и три следующих шага |
| `--state=openfail` | запрос «webhook ретрай»; ⏎ на строке заканчивается отказом |
| `--query=<текст>` | начальный запрос вместо того, что задаёт состояние |
| `--context=<имя>` | начальный контекст, по умолчанию `work` |
| `--slow-ms=<N>` | сколько миллисекунд «думает» источник |
| `--fail-open` | любая попытка открыть заканчивается отказом |

Ключа для прогрева больше нет: окно строится и прогревается при запуске всегда.

## Клавиатура

| клавиша | что делает |
| --- | --- |
| ↑ ↓ | выбор строки; ↓ на последней догружает следующую страницу |
| ⏎ | файл — открыть приложением по умолчанию; беседа — скопировать `claude --resume <сессия>`; в состоянии «ничего нет» — выполнить выбранный шаг |
| ⌘⏎ | файл — показать в Finder; у беседы вторичное действие не решено |
| ⇥ | граф выбранной строки; на графе — назад к выдаче, с тем же выбором |
| ⌘M | карта знаний контекста; на карте — назад к выдаче. Строка запроса на карте ищет |
| ← → ↑ ↓ | на графе и на карте: сдвинуть видимую зону на 15 % её ширины или высоты, с ⇧ — на 50 %; коротко плавно, удержание повторяет. Пока на карте есть найденное, ↑ ↓ ходят по нему, ← → двигают карту. Курсор в строке — ⌥← / ⌥→ |
| ⌥↑ / ⌥↓ | на графе: предыдущий и следующий узел (от фокуса к дальним), выбранный подводится в видимую часть; на карте — по найденному |
| + (и =) / − / 0 | на графе и на карте: приблизить и отдалить к середине видимой зоны, вписать всё. **Цена: там эти символы в строку поиска не печатаются** |
| ⌘= / ⌘- / ⌘0 | на графе и на карте: то же, что + − 0 (и кнопки − + ⤢ в шапке) |
| щипок, две пальца, ⌃ / ⌘ + колесо | на графе и на карте: щипок и колесо с модификатором приближают к курсору, две пальца и перетаскивание фона сдвигают |
| ⏎ на найденной сущности | на карте: поставить её в середину, масштаб прежний |
| клик по типу в легенде | на карте: спрятать или вернуть сущности этого типа |
| клик по сущности или связи карты | карточка: у сущности — описание и написания, у связи — цитата и источник |
| клик по узлу графа | беседа или файл — фокус на нём; остальное — карточка узла |
| ⌘1–4 | фильтр: Всё, Чаты, Файлы, Темы |
| ⌘K | следующий контекст: запрос повторяется в нём, выдачи не смешиваются |
| ⌘C | скопировать идентификатор сессии — когда открыть не удалось |
| esc | спрятать панель; на графе и на карте — назад к выдаче |

⌘1–4 и ⌘K действуют по-настоящему: меняют фильтр и контекст, и выдача меняется вместе с
ними. ⌘2 и ⌘3 у ядра — выбор группы на стороне панели: в запросе ядра фильтра нет. ⌘4
«Темы» у ядра честно говорит, что тем пока нет: ядро по теме не ищет.

⏎ и ⌘⏎ открывают по-настоящему — ровно три случая этапа UI-3: файл приложением по
умолчанию, файл в Finder, команда продолжения беседы в буфер обмена (строка внизу панели
говорит, что скопировано). Открыть беседу в самом инструменте панель не берётся — это
управление чужим приложением (раздел «Разрешения»). ⌘⏎ на беседе и ⌘C печатают в stdout,
что сделали бы. На графе ⏎ и ⌘⏎ делают то же с выбранным узлом, ↑↓ выбирают узлы. Строка клавиш внизу меняется вместе с состоянием, как в макете.

**Меню выбора контекста из макета не нарисовано.** ⌘K переключает на следующий контекст по
кругу — то же действие без меню. Шаг «Повторить в контексте …» на экране «ничего нет»
называет тот самый контекст, в который уйдёт ⌘K.

⌘-сочетания разбираются раскладко-независимо ([`KeyEquivalent.swift`](CrosskitPanel/KeyEquivalent.swift)):
под кириллицей `charactersIgnoringModifiers` у ⌘K даёт «л», а у ⌘3 — «і», и сравнение
с ней теряет сочетание молча.

## Шов

`CrosskitPanel/Feed/ResultFeed.swift` — протокол и типы. Форму задала панель, из того, что
стоит на экране; что из этого ядро умеет отдать сегодня, разобрано по полям в
[`docs/row-shape.md`](docs/row-shape.md). Это главный результат этапа UI-2.

Три реализации:

- `CoreFeed` — ядро. Процесс `crosskit --context <имя> search <запрос> --json` на страницу;
  ответ разбирает `CoreAnswer` — зеркало схемы `src/presentation/machine_answer.rs`, которое
  сверяет её номер первым. Отказ ядра приходит категорией, а не текстом, и панель показывает
  его состоянием экрана с заголовком «что случилось», а не пустым списком. Пустой запрос —
  подсказки того, что ядро понимает, а не «недавнее»: недавнего ядро не отдаёт.
- `InventedFeed` — маленький корпус в памяти, который **ищет по-настоящему** (набор сужает
  выдачу, страницы листаются курсором, счётчики считают непоказанное).
- `EmptyFeed` — источник, которому нечего отдать.

Новая буква отменяет запрос старой, и `CoreFeed` завершает его процесс, а не дожидается;
процесс, не ответивший за 10 с, завершается тоже. Медленный ответ на старую букву новую
выдачу не затирает — `AnswerOrder`.

Контексты у выдуманного источника не пересекаются, как и положено (ADR 0008): `work` держит
дерево целиком, `chats` — только беседы, `personal` настроен и не пройден. Поэтому ⌘K
меняет выдачу, а не только надпись в чипе.

Шов асинхронный, и это не украшение: открытие хранилища стоит 100–140 мс, сам запрос ~5 мс.
Панель не ждёт ответа синхронно и не замирает — пока ответ в пути, она показывает прошлую
страницу, помеченную «обновляется».

## Граф

⇥ на строке выдачи — граф с фокусом на ней: у беседы — `conversation:<сессия>`, у файла —
`path:<путь>`, оба поля строка уже несёт. Вид — процесс `crosskit --context <имя> graph --focus
<id> --depth 2 --json` (`GraphSource`, только у `CoreFeed`), с той же отменой и таймаутом, что у
выдачи. Выдуманный источник графа не рисует — касаний у него нет.

Рисует **Cytoscape.js 3.34.3** с раскладкой **dagre** (`cytoscape-dagre` 4.0.1) в `WKWebView`
(ADR 0046). Библиотеки вендорены в `CrosskitPanel/GraphPage/vendor/` с лицензиями, версии и
SHA-256 — в `NOTICE`. Страница грузится из бандла, сети у неё нет (CSP `default-src 'none'`),
навигация за пределы `GraphPage/` отменяется, данные приходят значением аргумента, а не кодом.

- `Feed/GraphAnswer.swift` — зеркало схемы 2 (`src/presentation/machine_graph.rs`);
- `Feed/GraphPicture.swift` — вид → элементы страницы: реплик на холсте нет, касание — линия
  «беседа → файл» с подписью («правила ×12 · вы назвали», «создала», «читала»), «только читала» —
  точками, «вы назвали» — акцентом; больше 12 линий — подписи только у выбранного узла;
- `GraphPage/graph.html`, `graph.js` — Cytoscape: раскладка слева направо (проект → беседа →
  файлы → другие беседы), стиль из токенов `Tokens.swift`, прозрачный фон;
- `View/GraphPage.swift` — веб-вид: создаётся при запуске, клавиатуру не берёт, принимает только
  `tap`, `rendered`, `ready`;
- `View/GraphScreen.swift` — нативное вокруг: строка-объяснение, строка о пустом шаге, легенда и
  карточка под холстом. Карточка файла называет реплику каждого касания и помечает её «определена
  по времени».

Клик по беседе или файлу — фокус на нём; по проекту, теме, файлу вне контекста — карточка.
⏎ — открыть файл или скопировать `claude --resume`, esc или ⇥ — назад к выдаче. Вид из сотни
узлов выше холста; его двигают и приближают так же, как карту знаний (раздел «Холст: клавиши и
жесты»), а узлы выбирают ⌥↑ / ⌥↓ и подводят выбранный в видимую часть.

## Холст: клавиши и жесты

Граф окрестности и карта знаний двигаются одинаково, и механизм у них один, не копия:

- `PanelWindow.swift` — **окно ловит клавиши и жесты** в `sendEvent`, раньше вида под курсором и
  строки запроса, пока на экране холст (`PanelContent.openCanvas`); на выдаче не ловит ничего;
- `Canvas.swift` — `CanvasKey`, разбор клавиши чистой функцией с тестами: стрелки, ⇧, + = − 0,
  ⌥↑ ⌥↓; `CanvasZoom` и вызовы камеры для любой из двух страниц;
- `View/GraphPage.swift` — страница знает, какой она холст, и шлёт ему `zoom`, `step`, `center`,
  `panBy`, `zoomBy`; жест разбирает `GraphWebView.gesture(of:)`: точная прокрутка трекпада — сдвиг,
  колесо мыши и прокрутка с ⌃/⌘ — масштаб, щипок — масштаб к точке под пальцами;
- `GraphPage/camera.js` — камера страницы: шаг клавиши — анимация 140 мс, удержание считает
  следующий шаг от цели прежнего; масштаб ×1,3 к середине, пределы 0,05–4; жест — сразу;
- `View/HeaderPieces.swift` — кнопки − + ⤢ шапки; `CanvasKey.hints` — общая часть строки клавиш.

Переопределить `magnify` в подклассе веб-вида было мало: у владельца щипок до него не дошёл, а
проба звала его напрямую и этого не видела. Распознаватель жеста на контейнере не выбран:
прокрутку он не ловит, и у щипка с колесом было бы два пути. Узлы графа выбирают ⌥↑ / ⌥↓, а не
⇥ / ⇧⇥: ⇥ на графе уже значит «к выдаче». Сами страницы масштаб не меняют
(`userZoomingEnabled: false`); прежний обработчик колеса в `graph.js` снят — до страницы колесо
больше не доходит.

## Карта знаний

⌘M — весь граф знаний контекста (ADR 0048): сущности и связи-факты, у каждой связи — цитата,
которую ядро нашло в источнике. Вид — процесс `crosskit --context <имя> knowledge map --json`
(`KnowledgeSource`, только у `CoreFeed`), один на открытие карты: дальше поиск и выбор идут без
ядра.

Рисует та же Cytoscape.js с встроенной **силовой раскладкой `cose`** — новых файлов в `vendor/`
нет. Страница — `GraphPage/knowledge.html`, второй веб-вид с той же границей, что у графа:
бандл, CSP без сети, данные значением аргумента; создаётся при первом ⌘M.

- `Feed/KnowledgeAnswer.swift` — зеркало `src/presentation/machine_knowledge.rs`;
- `Feed/KnowledgePicture.swift` — карта → элементы: цвет — место типа в словаре `[knowledge]`
  (`Tokens.knowledgePalette`, двенадцать цветов), размер — число связей по корню; фильтр — типы
  легенды и источник (корень или папка первого уровня под ним, с числом связей); поиск — по
  основе слова (ядро отдаёт основы имени, написаний и описания тем же анализатором, что у
  поиска), сначала совпавшие по имени, потом по описанию; все найденные подсвечены и названы
  списком; ничего — ближайшие имена по числу правок. Если по основе нет ничего, русское слово
  сверяется с латинскими основами по созвучию («контракт» — `contract` из `supplier_contracts`),
  и строка говорит «найдено по созвучию». Синонимы («договор» — «контракт») не ловятся;
- `GraphPage/knowledge.js` — раскладка с детерминированного старта (одна карта — одна картинка),
  перетаскивание фона; подписи 20 самых связанных видны всегда, остальные — когда их можно
  прочесть; связи — прямые без стрелок, стрелка и предикат — у подсвеченных и выбранной;
- сдвиг и масштаб — общие с графом окрестности, раздел «Холст: клавиши и жесты» ниже;
- `View/KnowledgeScreen.swift`, `View/KnowledgeWording.swift` — шапка со счётом, строка «что
  найдено», легенда типов, карточка. ⏎ на связи — открыть файл или скопировать `claude --resume`
  беседы.

**Предел — 400 сущностей**, самые связанные: раскладка растёт с квадратом карты (замер ниже).
За пределом шапка говорит «показано 400 из N — самые связанные», а поиск, не нашедший сущность,
говорит, что остальные — в терминале: `crosskit knowledge show <имя>`.

## Что умеет

- Глобальная ⌥Space из любого приложения, включая полноэкранное; разрешений не просит.
- Панель берёт клавиатуру, не активируя своё приложение: соседнее окно не теряет ни фокуса,
  ни строки меню, ни цвета заголовка.
- Пять состояний макета: выдача, пустое окно, набор запроса, «ничего не найдено», ошибка
  открытия. Окно меняет высоту вместе с содержимым, не двигая верхний край.
- Два вида строк: беседа и файл, с разными полями.
- Список выше 300 pt прокручивается, как в макете; счётчики и «Показать ещё» закреплены под
  ним, а не в конце прокрутки.
- Системный материал с размытием, светлая и тёмная темы следуют системной.
- Ширина 760 pt, радиус 16 pt, обводка `0 0 0 .5px`.

## Чего не умеет

- Не держит ядро открытым: каждая страница — новый процесс, и около 85 мс из 130 уходит не
  на запрос, а на старт процесса, открытие и закрытие графа (ADR 0044).
- Не знает времени файла: в ответе `search` его нет. Время беседы — есть, по последней реплике.
- Не открывает беседу в инструменте — только копирует команду продолжения.
- Меню выбора контекста не нарисовано — ⌘K переключает по кругу.
- Первый запуск не нарисован — слишком много неизвестного.
- Мышь — только клик по узлу графа; в выдаче выбор и прокрутка с клавиатуры.
- Режимы графа «Файлы / Знания / Происхождение» из макета не нарисованы переключателем: знания —
  отдельный экран, карта по ⌘M, а не режим окрестности строки. Глубина в панели — всегда 2.
- Карта знаний держит не больше 400 сущностей; остальные — только в терминале.
- Щипок на графе и на карте проверен только кодом: синтезировать жест увеличения оболочка не может. Он идёт
  тем же путём окна и тем же `GraphPage.gesture`, что и ⌃-колесо, — а оно проверено `--probe-gestures`
  доставкой через окно.
- Реплик на холсте нет (в макете — узлы-кружки): номер и момент реплики — в карточке файла, а
  текста у неё в графе нет, только роль и момент.
- Узла «+39 сообщений» из макета нет: сколько сообщений в беседе, сказано в карточке.
- Тень окна — системная тень `NSWindow`, а не трёхслойная тень макета.
- Подсветка совпавших слов — прямоугольник, а не скругление 3 pt: текстовая система AppKit
  скруглённого фона под диапазоном не даёт.
- Иконки приложения нет, в Dock оно не висит (`LSUIElement`).

## Что ждёт настоящих данных

Коротко; по полям — в [`docs/row-shape.md`](docs/row-shape.md). С этапа UI-3 у ядра панель
получает беседу как беседу (имя, сессию, число сообщений, время последней реплики) и одну
строку на файл; ниже — то, чего нет и сейчас.

- **Инструмент беседы.** Поля нет; эта сборка ядра читает транскрипты одного инструмента,
  Claude Code, и панель пишет его по этому факту, а не по полю.
- **Проект.** Узла проекта в графе нет. Граф (UI-4) рисует проектом корень контекста из
  конфигурации; у строки выдачи проекта по-прежнему нет, и подсказке `проект:` опереться не на что.
- **«3 из 16», «Ещё 13», «стр. 1 из 2».** Общего числа совпадений keyset-пагинация не
  считает. Панель печатает «стр. 1» — номер, который досчитала сама.
- **Диапазоны подсветки.** Ядро отдаёт совпавшие слова, панели нужны диапазоны.
- **«проход · 61 %», число репозиториев и файлов в контексте.** Не знаю, откуда их брать.

## Разрешения

**Продукт не просит ничего.** Горячая клавиша зарегистрирована через Carbon
`RegisterEventHotKey`: система отдаёт приложению одно сочетание и больше ничего не
показывает, поэтому разрешения за это не спрашивает. Приложение печатает это при запуске:

```
⌥Space зарегистрирована. Разрешений система не спрашивала.
```

Разрешение «Универсальный доступ» потребовали бы два других пути к глобальной клавише —
`CGEventTap` и `NSEvent.addGlobalMonitorForEvents`. Оба читают весь ввод человека, а не
одно сочетание, и спайк их не взял именно поэтому.

Разрешения понадобились **проверке**, а не панели: подделать нажатие ⌥Space нельзя без
«Универсального доступа», а снять экран — без «Записи экрана».

Отдельно на будущее: разрешение появится, если панель захочет вставить текст в чужое окно,
прочитать в нём выделение или управлять другим приложением. Это отдельное решение.

## Замер

От нажатия ⌥Space до обновления дисплея, на котором панель могла впервые оказаться на
экране. Двумя независимыми способами: изнутри процесса (`CADisplayLink`) и снаружи
(оконный сервер, [`tools/appear.swift`](tools/appear.swift)). MacBook, 1728×1117 pt,
восемь кругов.

| когда | первый вызов, изнутри | первый вызов, снаружи | установившийся, изнутри |
| --- | --- | --- | --- |
| UI-1, окно строится по нажатию | 183 мс | 251 мс | 8–12 мс |
| UI-1, окно строится при запуске | 82 мс | 141 мс | 7–11 мс |
| UI-1, плюс прогрев отрисовкой | 37 мс | 89 мс | 7–11 мс |
| **UI-2, прогрев в запуске, экран богаче** | **37 мс** | **84 мс** | **6–11 мс** |

Экран с тех пор вырос — фильтры, две группы, счётчики, прокрутка, — и на числа это не
повлияло. Прогрев платит за первую отрисовку там, где его никто не ждёт.

**Чем не мерил.** Первая версия замера ловила completion-блок транзакции CoreAnimation и
устойчиво давала 264 мс. Это была не отрисовка, а спящий run loop: блок лежал до
ближайшего пробуждения. Записано в
[`CrosskitPanel/FirstFrameProbe.swift`](CrosskitPanel/FirstFrameProbe.swift).

### Этап UI-3: от строки запроса до кадра на настоящих данных

`--replay=<файл>` подставляет запросы из файла в строку по одному, ждёт применённого ответа и
ближайшего кадра и печатает p50/p95 по отрезкам, затем выходит. Нажатия клавиши в замере нет —
подделать его без «Универсального доступа» нельзя.

```
sysctl -n vm.loadavg; ps -Ao pcpu,comm -r | head
"$APP/CrosskitPanel.app/Contents/MacOS/CrosskitPanel" \
  --core="$PWD/target/release/crosskit" --context=work --replay=<файл запросов>
```

| контекст | документов | p50 | p95 |
| --- | --- | --- | --- |
| `work` | 120 786 | 129–133 мс | 151–152 мс |
| `personal` | 4 843 | 115 мс | 126 мс |

Из них процесс ядра — 112 мс (запрос внутри — 28), разбор — 0,8, перестройка экрана — 6,7, до
кадра — 9,4. Под фильтром «Чаты» p95 — 414 мс: фильтра в запросе ядра нет, и панель
дочитывает страницы процесс за процессом. Числа, отрезки, состояние машины и вердикт — в
ADR 0044.

## Чем проверялось

- [`tools/appear.swift`](tools/appear.swift) — проверка снаружи процесса: отправляет
  нажатие и опрашивает оконный сервер, пока окно панели не станет экранным. Вторым режимом
  печатает строку в ключевое окно настоящим Unicode-событием.
- Протокол в stdout самого приложения: кто был фронтом до и после показа, чьё меню в строке
  меню, ключевое ли окно, на активном ли Space, размер окна.
- `kill -USR1 <pid>` показывает и прячет панель мимо горячей клавиши. Это affordance
  проверки, а не путь продукта: без «Универсального доступа» подделать нажатие нельзя.
