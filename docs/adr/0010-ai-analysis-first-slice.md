# ADR 0010: AI-анализ, первый срез Insight Layer

Статус: принято 2026-09-21 (Этап 6)

_Поправка 2026-10-05 (ADR 0048):_ вопрос модели — тема, сущности и связи с цитатой в одном
ответе; ключ кэша — пять частей, пятая — отпечаток словаря типов. Попадание в кэш теперь читает
куски ревизии: факты проверяются цитатой против кусков той ревизии, что спросила, — но к
провайдеру по-прежнему не обращается и ничего не тратит.

## Контекст

С этапа 5 задание доходит до результата, но результат детерминированный: число чанков и
сумма их байтовых диапазонов. Обработчик — порт, и гнездо под модель готово.

Главное решение принято заранее и не обсуждается: **содержимое покидает машину только там,
где контекст это явно разрешил, умолчание — запрет**. Рабочий контекст, где лежат файлы
работодателя, по умолчанию не имеет права отправить наружу ни байта.

## Решение

### Граница: не проверка, а отсутствие значения

У контекста появилось свойство `send_content_outside`; отсутствует — значит нет.

Разрешение выражено типом, а не флагом:

```rust
ContentEgress::Allowed.permit() -> Some(ContentEgressPermit)
ContentEgress::Denied.permit()  -> None
```

`ContentEgressPermit` нельзя сконструировать снаружи модуля. Его требуют по значению:

- `DescribedInsightHandler::new(..., permit)` — обработчик, который обращается к модели;
- `InsightRequest::new(content, permit)` — то, что отправляется;
- `RevisionInputReader::read_text(job, permit)` — единственная функция, достающая
  содержимое файла обратно из графа.

В запрещающем контексте permit'а нет, поэтому **ни одного из трёх объектов не существует**.
Это не «вызов вернул отказ» — собрать вызов не из чего. Проверка, которую можно забыть,
заменена значением, которого нет.

Проверено поведением, а не чтением кода: smoke-тест ставит `ANTHROPIC_API_KEY` в мусорное
значение, запускает `index jobs run` в запрещающем контексте и требует `Completed jobs: 1`.
Если бы запрос собрался, он ушёл бы в сеть с отвергаемым ключом и задание вернулось бы
`failed`.

### Порт провайдера

`InsightProvider::describe(InsightRequest) -> Result<ModelAnswer, InsightFailureCategory>`
в application: ни HTTP, ни типов вендора, ни имён моделей в сигнатуре. Инфраструктура
реализует один провайдер; под ним — ещё один порт, `MessageTransport`, за которым остаётся
всё сетевое. Поэтому каждый тест модельного пути, кроме одного, идёт без сети и без ключа.

Детерминированный обработчик остался и стал `CountedInsightHandler`: он работает без ключа
и в запрещающем контексте, и намеренно ничего не заключает — сообщает, чему равен вход, и
останавливается. Оба обработчика читают вход через один и тот же порт, так что одного
запроса к графу не существует в двух копиях.

### Строгая схема, дважды

В запросе идёт `output_config.format` с JSON-схемой `{topic, confidence}` — сервис сам
ограничивает ответ. Но обещание сервиса не граница, поэтому пришедшее проходит через
доменный конструктор:

- `topic` — непустая строка после trim, не длиннее 120 символов, **одна строка без
  управляющих символов**;
- `confidence` — конечное число в `0..=1`.

Ограничение длины — не опрятность. Метка пишется в граф; метка без потолка — это способ
для содержимого файла оказаться в графе под другим именем.

Сырой ответ не сохраняется и не печатается. Отказ — категория и больше ничего.

### Бюджеты в байтах, а не в токенах

Два предела: на задание и на прогон. Считаются в байтах текста чанков, потому что байты
известны точно и **до чтения**: граф хранит диапазон каждого чанка, поэтому задание сверх
предела отвергается, не загрузив содержимое в память. Токен-счёт был бы оценкой или ещё
одним запросом.

Пределы падают по-разному, и это отражено категориями: ревизия больше предела задания
будет такой же и в следующий раз (`input-too-large`, постоянное), а прогон, потративший
своё, полон исправных заданий (`budget-spent`, временное).

### Кэш по входу

Ключ — композиция четырёх вещей: отпечаток содержимого, версия конвейера, идентификатор
модели, версия запроса. Части длино-префиксованы, поэтому одна не может быть прочитана как
начало следующей. Хеша нет: ключ читаем и не несёт ни пути, ни содержимого.

Кэш лежит в базе контекста. Это снова граница: ответ, купленный для файла одного контекста,
лежит там, куда другой контекст не дотянется.

Попадание в кэш не читает содержимое, не обращается к провайдеру и ничего не тратит.
Прочитанная запись проходит тот же конструктор, что и свежий ответ: то, что лежит на диске,
обязано всё ещё быть темой, иначе оно не выдаётся.

### Категории отказов в жизненном цикле этапа 5

Категория теперь говорит и о том, поможет ли повтор. Переходы не менялись — `failed →
queued | dead` были и остались; решение получило второй вход:

| Категория | Что значит | Повтор |
| --- | --- | --- |
| `unavailable` | сеть, 429, 5xx, таймаут | да |
| `budget-spent` | прогон потратил своё | да |
| `handler` | обработчик не смог | да |
| `lease-expired` | захват кончился раньше worker'а | да |
| `schema` | ответ не той формы | нет |
| `refused` | модель отказалась | нет |
| `input-too-large` | ревизия больше предела | нет |
| `input` | граф не держит того, что называет задание | нет |

Постоянное уходит в `dead` сразу, не тратя оставшиеся попытки на тот же конец.

### Без ключа worker не крутится вхолостую

Разрешающий контекст без ключа: причина печатается один раз, команда выходит нулём, **ни
одно задание не захвачено**. Захват потратил бы попытки на вызов, которого не будет, а
тихий откат к детерминированному обработчику закрыл бы задание навсегда — `done`
не анализируется повторно.

### Модель и зависимость

Идентификатор модели конфигурируем, умолчание — `claude-haiku-4-5-20251001`. Сверено с
официальной справкой, а не по памяти: оттуда же — что `temperature`, `top_p`, `top_k` и
`budget_tokens` на текущих моделях дают 400 и не отправляются, что `effort` живёт внутри
`output_config`, и что уровень усилия принимают не все модели.

Умолчание выбрано под форму работы, а не по верхушке линейки. Задание — одна короткая метка
темы на ревизию, по схеме из двух полей, с потолком метки в 120 символов; очередь на
настоящем дереве — десятки тысяч таких заданий.

Цены с официальной справки на 2026-09-21, за миллион токенов:

| Модель | Вход | Выход | Контекст | Batch |
| --- | --- | --- | --- | --- |
| `claude-opus-5` | $5.00 | $25.00 | 1M | −50% |
| `claude-sonnet-5` | $2.00 | $10.00 | 1M | −50% |
| `claude-haiku-4-5-20251001` | $1.00 | $5.00 | 200K | −50% |

Расчёт на измеренном корпусе: 135 индексируемых текстовых файлов этого репозитория, средний
11 765 байт. **Токены оценены из байтов, а не измерены** — `count_tokens` требует ключа.
Учтено, что Opus 5 и Sonnet 5 используют токенизатор, введённый с Opus 4.7 (примерно на 30%
больше токенов на тот же текст), а Haiku 4.5 — предыдущий.

| Модель | Вход, токенов на ревизию | 10 000 ревизий | То же с «думаньем» ~300 выходных токенов |
| --- | --- | --- | --- |
| `claude-opus-5` | ~3 810 | $198 | $266 |
| `claude-sonnet-5` | ~3 810 | $79 | $106 |
| `claude-haiku-4-5-20251001` | ~2 900 | **$31** | — |

Три факта из справки весят здесь больше цены. `effort` не поддерживается на Haiku 4.5 —
поэтому умолчание `effort` пустое, и поле не уходит в запрос; модель, которая его принимает,
задаётся вместе с уровнем. Лимиты RPM/ITPM/OTPM у Opus 5, Sonnet 5 и Haiku 4.5 на каждом
тарифе совпадают, поэтому пропускная способность выбор не определяет. Кэш промпта здесь
не работает: каждый документ уникален, а системная подсказка короче минимального
кэшируемого префикса.

Умолчание — датированный снимок, а не алиас `claude-haiku-4-5`: алиас позволил бы другой
модели, с другой ценой и другими ответами, приехать сюда молча.

**Записанный долг: качество не измерено.** Сравнить метки самой дешёвой и средней модели на
двух-трёх десятках настоящих ревизий не удалось — в среде не было ключа: `ANTHROPIC_API_KEY`
не задан, CLI `ant` не установлен, профиля в `~/.config/anthropic/` нет. Умолчание выбрано
по нагрузке и цене, и это заявлено прямо, а не выдано за проверенное качество. Долг дешёвый:
30 ревизий среднего размера — около $0.09 на Haiku и $0.60 на Opus 5, меньше доллара за оба
прогона. Когда ключ появится, сравнение проводится и его результат дописывается в эту ADR
таблицей. Риск ограничен тем, что модель конфигурируема, а задания перезапускаемы.

**Кандидат, не решение: Batch API.** Очередь не интерактивна, и пакетная обработка даёт
−50% на вход и выход при тех же ценах. Это меняло бы форму исполнителя — асинхронная сдача
и опрос вместо вызова по заданию, — поэтому здесь записано как кандидат и намеренно не
реализовано.

Отдельно: серверный `fallbacks` на отказ модели **не включён**. Постановка этапа прямо
называет отказ модели постоянным исходом, а fallback молча увёл бы запрос на другую модель.
Это отменяемое решение, и оно записано здесь, чтобы было что отменять.

HTTP в std нет. Выбран `ureq 3.4.2` с rustls: блокирующий, без async-рантайма, с явными
таймаутами, 17 крейтов в дереве — против tokio+hyper+h2 у `reqwest`. Ни один уже
зафиксированный пин не сдвинулся, offline-сборка проходит. Клиент целиком за
`infrastructure/anthropic/https_transport.rs`; выше него типов ureq нет.

Endpoint — константа, не конфигурация: программа, которую можно перенаправить правкой
файла, — это программа, чьё содержимое можно увести правкой файла. Ключ читается только из
`ANTHROPIC_API_KEY`: конфиг копируют, диффят и вставляют.

### Схема v11

```text
ALTER TABLE InsightResult ADD produced_by, model_id, prompt_version, topic STRING DEFAULT '';
ALTER TABLE InsightResult ADD confidence DOUBLE DEFAULT 0.0;
ALTER TABLE InsightResult ADD input_tokens, output_tokens INT64 DEFAULT 0;
CREATE NODE TABLE InsightCacheEntry(key PRIMARY KEY, topic, confidence, produced_by,
                                    model_id, prompt_version, input_tokens, output_tokens,
                                    created_at_unix_ms);
```

Записи этапа 5 сохраняют свои счётчики и получают пустую тему без модели и без токенов —
честная запись о находке, за которую никто не платил. Запись задания не менялась ни одним
оператором: вердикт **C** не понадобился.

## Инварианты

1. В контексте с запретом исходящий запрос не собирается: объекта, который его собрал бы,
   не существует.
2. Содержимое файла достаётся из графа только по permit'у.
3. Ответ модели становится значением только через доменный конструктор; всё прочее —
   `schema`.
4. Задание сверх предела входа отвергается, не прочитав содержимое.
5. Одинаковый вход в одном контексте оплачивается один раз.
6. Ни сырого ответа, ни промпта, ни содержимого — ни в записи задания, ни в выводе команды.
7. Без ключа в разрешающем контексте не захватывается ни одно задание.

## Что не входит в этап 6

Несколько видов инсайта и ветвление по типам файлов; entity resolution, противоречия и
подтверждение; `crosskit ask`; поиск, эмбеддинги и UI; батч-API и token budgets;
несколько провайдеров.

## Последствия

Insight Layer перестал быть гнездом и стал работать, не сдвинув ни жизненный цикл, ни
границу контекстов. Поиск (этап 7) получает тему ревизии как ещё один сигнал ранжирования.
