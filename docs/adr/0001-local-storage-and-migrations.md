# ADR 0001: локальное хранилище и миграции LadybugDB

Статус: принято 2026-09-18

## Контекст

Crosskit хранит производный локальный граф, но не оригиналы файлов. Перед первой
миграцией необходимо зафиксировать место хранения, жизненный цикл `Database` и
способ изменения схемы.

## Решение

- Используем `lbug 0.20.4` как embedded-хранилище.
- На macOS путь по умолчанию:
  `~/Library/Application Support/Crosskit/graph.lbug`. На остальных платформах —
  `$XDG_DATA_HOME/crosskit/graph.lbug`, либо `~/.local/share/crosskit/graph.lbug`.
  `CROSSKIT_DATA_DIR` явно переопределяет родительский каталог; это нужно для
  изолированных запусков и будущей настройки приложения.
- Один `LadybugGraphRepository` владеет одним `Database` и сериализует записи mutex-ом.
  `enable_multi_writes` остаётся выключенным. Фоновый сервис позже станет единственным
  владельцем этого объекта между CLI-процессами.
- Миграции — нумерованные неизменяемые Cypher-наборы. Таблица `SchemaMigration`
  фиксирует применённую версию и имя. Каждая неприменённая миграция выполняется вместе
  с marker-записью в одной транзакции.
- Первая схема не загружает расширения LadybugDB. FTS, vector, algo, json и Arrow
  подключаются только отдельной миграцией и compatibility-тестом.

## Последствия

`crosskit doctor` создаёт каталог и применяет миграции, поэтому пользователь явно
видит место локального хранения. База не рассчитана на одновременное read-write
открытие несколькими процессами до появления `crosskitd` и IPC.
