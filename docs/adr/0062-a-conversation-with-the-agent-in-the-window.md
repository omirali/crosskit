# ADR 0062: беседа с агентом в окне

Статус: принято 2026-10-30 (этап D-3, первая часть — Claude Code), ждёт приёмки владельца.
Схема графа не меняется. Номер машинного ответа не меняется (2): у беседы в `tasks --json`
добавлено поле `working_directory`.

## Контекст

Окно показывало задачу и решения по ней (ADR 0059, 0061), а работа с агентом шла в отдельном
терминале. Владелец поставил задачу: беседа с Claude Code прямо из окна, и окно показывает
поток — не запускает молча. По сути, свой чат.

## Что проверено до кода

Установленный Claude Code 2.1.41 проверен тремя крошечными беседами на `haiku` во временном
каталоге, без сохранения журнала, всего около 7 центов. Протокол оказался таким.

- **Запуск:** `claude -p --input-format stream-json --output-format stream-json --verbose
  --include-partial-messages`.
- **Сообщения человека** — строки JSON на ввод.
- **Что приходит обратно:**
  - `system/init` с сессией, каталогом и моделью;
  - куски текста в `stream_event` (`content_block_delta`);
  - сообщение модели целиком (`assistant`) с текстом и вызовами инструментов;
  - результат инструмента (`user`, `tool_result`);
  - итог хода (`result`) со стоимостью и длительностью.
- **Запрос разрешения.** С `--permission-prompt-tool stdio` CLI спрашивает разрешение в том же
  потоке: `control_request` с `can_use_tool` (инструмент, вход, подсказки). Ответ
  `control_response` с `behavior: allow` и исходным входом CLI принял и выполнил действие.
- **Настройки владельца подхватываются:** MCP, правила, разрешения. `echo` прошёл без
  вопроса, потому что так разрешено в его настройках.
- **В режиме потокового ввода CLI молчит до первого сообщения.** `init` приходит после него.
  Тест, который ждал `init`, чтобы заговорить, завис; поддельный `claude` в тестах теперь ведёт
  себя как настоящий.

## Решения

1. **Беседа — настоящая беседа Claude Code.** Без `--no-session-persistence`: её журнал
   сохраняется, как у беседы из терминала. Служба его прочитает, и сшивка найдёт задачу.
   Настройки, правила и MCP — владельца.
2. **Окно ничего не прячет и ничего не разрешает за человека:**
   - текст идёт кусками по мере ответа;
   - каждый вызов инструмента виден с результатом;
   - каждый запрос разрешения — карточка «Разрешить / Отклонить»;
   - «Стоп» прерывает ход (`control_request` с `interrupt`), беседа остаётся;
   - запрос, которого окно не умеет, получает отказ, чтобы CLI не ждал вечно.

   Режим разрешений выбирается перед началом: как в настройках владельца, правки файлов без
   спроса или только план.
3. **Новая беседа получает вводную задачи** (`TaskBrief`, через `--append-system-prompt`):
   - основная линия — что выбрано, кем и почему;
   - что отклонено и отложено с причинами;
   - где задача ждёт решения;
   - открытые риски critical и high и риски, о которых владелец уже решил.

   Это смысл карты для агента (`docs/decision-map.md`, раздел 8): он не предлагает отвергнутое
   снова. Вводная видна владельцу до начала беседы.
4. **Где работает агент.** У беседы в `tasks --json` есть `working_directory` — первый `cwd`
   её журнала. Чтение останавливается на первой строке с ним: журнал бывает в десятки мегабайт.
   «Продолжить задачу» начинает новую беседу в каталоге последней беседы задачи, чей журнал
   ещё на диске. Если такой нет, каталог выбирает человек. «Продолжить» у беседы продолжает её
   (`--resume`) в её каталоге.
5. **Новая беседа входит в задачу сама.** После каждого хода окно отдаёт службе решение
   `add`. Пока служба беседу не прочитала, книга отвечает `unknown-conversation`, и окно
   спросит снова после следующего хода.
6. **Запуск — через login-оболочку**, как построение карты (`LoginShell`, общий для обоих).
   Беседа видит тот же PATH, что терминал, а аргументы — имя задачи, вводная — не становятся
   командой. `CLAUDECODE` из окружения убирается.
7. **Беседа — своё окно** (`WindowGroup` по `ChatTarget`), его можно держать рядом с картой.

## Проверено

- Разбор потока — на строках в формате, который пишет Claude Code 2.1.41, с выдуманными
  данными.
- Аргументы `claude`. Беседа сохраняется: `--no-session-persistence` среди аргументов нет.
- Целый ход с поддельным `claude`: поток, запрос разрешения, ответ окна, конец хода. Ответ
  «можно» возвращает вход инструмента без правок.
- Вводная: выбранное, отклонённое с причиной, HEAD с вариантами, открытые риски; находок вне
  задачи в ней нет.
- Живой ход настоящего `claude` из Swift-кода пакета: текст двумя кусками, итог, 0,7 цента.
  Проверка включается переменной окружения.
- Рабочий каталог на настоящей задаче: у трёх последних бесед он есть, у семи журналов уже
  нет — Claude Code удаляет их примерно через месяц.

## Попутно: перезапуск службы оборвал запись графа

На этом этапе служба была перезапущена (`service restart`), пока контекст `work` был в проходе.
`personal` остановилась чисто («Stopping… Watch stopped»), а у `work` строки об остановке нет.
Новый процесс стартовал через 62 секунды, хотя `ExitTimeOut` агента — 120. Журнал записи `work`
остался оборванным, а отчёта о сбое не было.

Граф восстановлен:
- файлы склонированы в `…/Crosskit/incident-20261030-b/`;
- `index recover` убрал журнал в сторону с первой ступени.

Почему процесс исчез раньше срока, не установлено. Системный журнал launchd ничего не показал.
Гипотеза: launchd останавливает агента раньше `ExitTimeOut`, а длинный проход `work` за это
время не заканчивается.

До исправления службу нельзя перезапускать, пока идёт проход. Исправление — останавливать
проход на границе пакета: закоммитить сделанное и выйти. Это следующий шаг по службе.

  или продолжение одной.
- Окно не показывает, как растёт карта по ходу беседы: карта достраивается командой после.
