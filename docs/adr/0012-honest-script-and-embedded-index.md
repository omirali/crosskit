# ADR 0012: честное поле письменности и встроенный поисковый индекс

Статус: принято 2026-09-22 (Этап 8)

## Контекст

ADR 0011 закрыл два пути к поиску: FTS-расширение движка и собственный инвертированный
индекс в графе. Направление выбрано — индекс вне графа, в процессе, на чистом Rust, по
индексу на контекст. Граф остаётся единственным источником истины, индекс — производная.

Перед спайком надо было убрать одно препятствие, которое спайк иначе унаследовал бы:
поле `language` на чанке говорило неправду.

## Решение 1: поле называет то, что вычислено

Было: `language = if text.is_ascii() { "en" } else { "und" }`, и решалось один раз на файл.
Английский код был `en` по совпадению, русская проза — `und`, файл с обоими — `und`
целиком. Никто этого не вычислял; это лежало в графе как факт.

Стало: `script`, доменный тип `ChunkScript`, значение на чанк, а не на файл:

| Значение | Что означает |
| --- | --- |
| `latin` | есть латинские буквы, кириллических нет |
| `cyrillic` | есть кириллические, латинских нет |
| `latin+cyrillic` | есть и те и другие — обычный случай этого корпуса |
| `neither` | букв ни одной из двух письменностей нет: цифры, пунктуация или письменность, которую Crosskit не нормализует |

Это не определение языка и не становится им от частого чтения. Латиница — ASCII плюс
буквы Latin-1 Supplement и Latin Extended-A/B; кириллица — Cyrillic и Cyrillic Supplement.
Письменность, которую нормализовать нечем, попадает в `neither`, а не в догадку.

Значение считается по тексту самого чанка, поэтому ловушка этапа 2S не возвращается: тогда
язык пересчитывался для каждого чанка сканированием **всего** файла, что давало
квадратичную стоимость. Здесь каждый чанк читается один раз, с ранним выходом.

**Миграция v12** пересчитывает значения из текста, который уже лежит в графе: ничего не
читается с диска. Бэкфилл написан на Rust, а не на Cypher, и это не вкус: правило —
`ChunkScript::of`, и второе его воплощение на другом языке совпадало бы с первым ровно до
первого расхождения. Страницы keyset по 200 чанков, потому что текст чанка тяжелее строки
ревизии.

**Найденный дефект движка, который важнее самой миграции.** Первая версия добавляла колонку
`script` и удаляла `language`. `ALTER TABLE ContentChunk DROP language` движок принимает, и
после этого таблица нечитаема: первый же доступ по первичному ключу умирает в
`ColumnChunk::lookup` по нулевому указателю — SIGSEGV, весь процесс, а не ошибка, которую
можно обработать. Проверено прогоном миграции в обоих вариантах на lbug 0.20.4; отчёт
падения приложен к стеку `PrimaryKeyScanNodeTable`. Поэтому миграция **переименовывает**
колонку, а не пересоздаёт её, и записано правило: **ни одна миграция не удаляет колонку из
таблицы со строками**, пока это не исправлено. Теста на это нет и быть не может — он уносил
бы весь тестовый бинарь.

## Решение 2: кандидат — tantivy, и он проходит

`tantivy 0.26.2`, MIT. Чистый Rust: в выбранном наборе фич ни одной C-зависимости не
остаётся — см. ниже про zstd.

**Offline.** После однократной выборки зависимостей сборка и тесты идут без сети. Ни одного
скачиваемого блоба в рантайме — ровно то, чем расширение FTS не было.

**Вес.** Названо числом, потому что проект держался скромно:

| | Крейтов |
| --- | --- |
| Дерево проекта до | 89 |
| Дерево проекта после (tantivy в dev-dependencies) | 170 |
| Поддерево самого tantivy | 108 |
| **Добавляет крейтов** | **+81** |
| Production-бинарь (normal deps) | 74, без изменений |

Пока tantivy — dev-dependency, production-бинарь не меняется вовсе. Перевод его в обычные
зависимости на этапе реализации и есть та цена: дерево почти удваивается. Лицензии всех 111
крейтов поддерева permissive — MIT, Apache-2.0, BSD-3-Clause, Zlib, Unicode-3.0; copyleft
нет.

**Столкновение zstd, которое сначала выглядело предупреждением, а на Linux оказалось
блокирующим.** Движок статически несёт zstd внутри `liblbug.a`, и фича tantivy
`columnar-zstd-compression` — она входит в набор по умолчанию — приносит `zstd-sys` со своей
копией. На macOS линковщик ограничивается предупреждением о дублирующихся символах; **на
Linux `/usr/bin/ld` отказывается собирать вовсе**: `multiple definition of
'ZSTD_getCParams'` и ещё десятки, `collect2: error: ld returned 1 exit status`. Найдено
контейнерным прогоном — на macOS этого было не видно.

Снимается выбором фич, а не обходным путём: `default-features = false` и явный набор
`mmap`, `stopwords`, `lz4-compression`, `stemmer`. Сжатие хранилища — lz4, которого движок
не несёт; zstd из дерева уходит совсем. Побочно дерево стало меньше на восемь крейтов. Это
не настройка на вкус, поэтому причина записана прямо в `Cargo.toml`: вернуть набор по
умолчанию значит снова не собрать проект на Linux.

### Двуязычие: выбор письменности на токен, а не на индекс

То, чего не мог ни один отклонённый носитель. Расширение стеммит индекс целиком одним
алгоритмом, поэтому двуязычный корпус теряет один из языков. Здесь выбор — на токен:
`обходит` стеммится по-русски, `reconcile` по-английски, внутри одного предложения.

Языка по-прежнему никто не определяет: читается письменность букв — то же узкое проверяемое
свойство, что записывает `ChunkScript`. Токен, который не целиком одной письменности
(`сервerный`) и токен из цифр не стеммятся вовсе: прогнать по ним Snowball значит
придумать основу.

Разбиение — правило `SimpleTokenizer`, `!char::is_alphanumeric()`. Оно снимает второй дефект
расширения: русские «ёлочки» там разделителями не были, и слово в кавычках становилось
токеном `«слово»`, ненаходимым по своей же форме — 108 таких токенов в корпусе ADR 0011.

Полнота и точность на том же корпусе и тех же группах словоформ, что в ADR 0011. Эталон
построен по объявленным поверхностным формам, **без участия проверяемого стеммера**:
строить его анализатором индекса значило бы спрашивать, находит ли индекс то, что его же
стемминг считает присутствующим.

| Конфигурация | Полнота RU | Точность RU | Полнота EN | Точность EN |
| --- | --- | --- | --- | --- |
| расширение, `none` | 0.21 | 1.00 | 0.28 | 1.00 |
| расширение, `english` | 0.21 | 1.00 | 0.95 | 0.99 |
| расширение, `russian` | **0.96** | 0.96 | 0.28 | 1.00 |
| **спайк, выбор на токен** | **0.96** | 0.94 | **1.00** | 0.99 |

Цель — не уступить `russian` по русскому и `english` по английскому одновременно —
достигнута: 0.96 против 0.96 и 1.00 против 0.95, одним индексом. Точность по русскому на
0.02 ниже, чем у `russian`; это честная цена и она названа.

### Цена, рядом с числами ADR 0011

Корпус — текст этого репозитория: 3598 абзацев, 1.29 МБ, русская проза с английскими
идентификаторами.

| Что | Графовый индекс (ADR 0011) | Встроенный индекс |
| --- | --- | --- |
| Запись | 1.4 с/МБ | **0.13–0.14 с/МБ** |
| Размер относительно текста | ~7.8 МБ фикс + ~6.3× (расширение) | **0.42× текста** |
| Задержка запроса, медиана | ~0.95 мс | **RU 329 мкс, EN 342 мкс** |
| Задержка, p90 | — | RU 446 мкс, EN 362 мкс |

Запись примерно в десять раз дешевле графового варианта, а индекс меньше текста, а не
кратно больше его.

**Память.** Те же три измерения в контейнере `rust:1-trixie` под `-m 1g --memory-swap 1g`
проходят; пик по cgroup — 475.8 MiB на все три прогона подряд, каждый из которых строит
полный граф корпуса заново. Это верхняя граница на контейнер, а не на индекс: доминирует
буферный пул открытой базы (проект знает его как ~256 MiB постоянной части), плюс страничный
кеш. На Linux всё, что меряли, ещё дешевле: сборка 0.05–0.06 с/МБ, медиана запроса 166–167
мкс, а полнота и точность те же — RU 0.96/0.93, EN 1.00/0.99.

### Три свойства, которых у графового варианта не было

**Изоляция** держится хранением, как в ADR 0008: у контекста свой каталог индекса, общего
индекса с колонкой контекста нет. Запрос не может достать чужой текст, потому что чужих слов
нет в файлах, которые открывает этот searcher. Закреплено сентинел-тестом: уникальная строка
в одном контексте не находится из другого ни одним из семи запросов, включая `*` и
поле-квалифицированный.

**Восстановимость.** Индекс не хранит ничего, чего нет в графе. Тест сносит каталог целиком,
строит заново, и сверяет: число документов совпадает с числом чанков, ответы совпадают,
**граф не изменился** — перестроение только читает. Переоткрытие с диска тоже проверено, и
оно доказывает попутно, что анализатор регистрируется при открытии: индекс хранит имя
анализатора, а не его поведение.

**Рассинхронизация обнаруживается сравнением числа документов с числом чанков графа.** Это
сигнал, а не доказательство, и разница названа: равные числа теоретически могли бы скрыть
подмену. Для той поломки, ради которой признак существует, он корректен: tantivy коммитит
атомарно, поэтому прерванная сборка оставляет индекс на предыдущем коммите — строго позади
графа, никогда впереди. Починка — перестроение, и именно поэтому более дорогая проверка не
окупается: неверный ответ здесь лечится выбрасыванием индекса, что дёшево ровно потому, что
истина у графа.

## Последствия

- Схема v12. `ContentChunk.language` больше не существует; `script` заполнен пересчётом.
- `tantivy` и `rust-stemmers` — dev-dependencies; production-бинарь их не несёт и о них не
  знает. Весь спайк — `cfg(test)`, в CLI нет ни одной команды поиска.
- Правило: миграции не удаляют колонки, пока `DROP` роняет движок.
- Числа сняты на macOS arm64, кроме контейнерных; корпус — этот репозиторий, поэтому он
  меняется вместе с ним. Это baseline, не порог приёмки.
