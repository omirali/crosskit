# ADR 0051: задача сшивается из бесед, карта решений строится по запросу

Статус: принято как направление 2026-10-29, замер сшивки снят в тот же день (последний раздел)
и ждёт разметки владельца. Концепция — `docs/decision-map.md`, её проверил
владелец. Решения 1–3 действуют сейчас: этап «Сшивка бесед» меряет их на машине владельца.
Решения 4–5 описывают следующий этап и до него в коде не появляются.

## Контекст

Владелец работает с агентами в Claude Code и Codex. Одна задача у него идёт неделями и проходит
через десятки бесед. Новая беседа начинается, когда заполнен контекст, по handoff-файлу. Другая
платформа подключается, когда кончился лимит подписки. Рядом идут QA-беседа и пакетные
исполнители. Внутри одной беседы смешаны ветки решений, брошенные вопросы и забытые риски.

Концепция `docs/decision-map.md` отвечает на это так: задачу показывают картой решений, а не
списком чатов. Чтобы построить карту, нужно сначала знать, из каких бесед состоит задача.

На первом разборе настоящей задачи владельца (`quarry`, раздел 10 концепции) кандидатов
оказалось около 35 бесед Claude Code за 2,5 месяца, в двух рабочих каталогах. Одна месячная беседа
размечена моделью за ≈460 тысяч токенов.

Перепись сначала ошиблась, и ошибка показательна. Около 23 бесед августа–сентября нашлись в
хранилище Codex и были приняты за сессии Codex. На деле это беседы Claude Code: Codex Desktop
импортировал их историю. Claude Code тем временем удалил оригиналы: самый старый его файл на
машине датирован 28 сентября, на месяц позже начала задачи. Копия в Codex хранит только текст
реплик, без вызовов инструментов. Собственная работа в Codex — одна сессия с 16
субагентами-исполнителями и 16 сессиями автоматического ревьюера.

Сегодня Crosskit знает беседу Claude Code как беседу (ADR 0036, 0041: имя, реплики, касания), а
сессии Codex только считает. Задачи как сущности нет нигде.

## Решение 1: задача — сущность Crosskit, к ней относятся отрезки бесед

Задача — это не каталог, не репозиторий и не беседа:
- одна задача идёт в нескольких каталогах;
- в одном каталоге живут разные задачи;
- в одной беседе бывают куски разных задач.

Поэтому к задаче относится **отрезок** беседы. Переход от одной беседы к следующей — ребро
«продолжение» с причиной, когда её видно: заполнен контекст, кончился лимит, другая платформа.

Служебные сессии беседами не считаются: автоматический ревьюер команд, субагенты, пакетные
исполнители по одному протоколу. Пакет одинаковых сессий — один узел «пакетная работа».

**Платформу беседы определяет её происхождение, а не место хранения.** Беседа Claude Code,
которую Codex импортировал к себе, остаётся беседой Claude Code. Если оригинал ещё лежит в
`~/.claude/projects`, в задаче она встречается один раз. Если оригинал удалён, копия в Codex
становится единственным источником, и Crosskit читает её. У такой копии нет вызовов
инструментов, поэтому признак «файл-эстафета» для неё доступен только по тексту реплик.

Отклонено:

| вариант | почему нет |
| --- | --- |
| задача = беседа | на разобранном примере задача — около 35 бесед на двух платформах |
| задача = каталог или репозиторий | в каталоге разобранной задачи живут ещё как минимум две другие задачи |
| задача = беседа целиком, без отрезков | побочная находка из разобранной беседы попала бы в чужую задачу; так и случилось при ручном сведении |

## Решение 2: беседы сшиваются по признакам, а не моделью

Признак связи — это наблюдаемый факт в журналах двух бесед, а не догадка. Признаки идут от
сильных к слабым:

| признак | что видно в журналах | сила |
| --- | --- | --- |
| файл-эстафета | беседа B ссылается на файл, который написала беседа A | факт |
| беседа названа | реплика владельца в B содержит имя беседы A | факт |
| одна ссылка на трекер | одна и та же ссылка на задачу трекера в обеих | факт |
| одна ветка | одна и та же git-ветка, не основная | сильный |
| общие файлы | обе писали одни и те же файлы | сильный |
| соседство | B началась вскоре после конца A в том же каталоге | слабый |

Кандидат в задачи — это связная группа бесед по признакам с силой «факт» и «сильный».
Слабые признаки кандидата не создают: они только подсказывают человеку, что стоит посмотреть.
Модель на этом шаге не вызывается. Сшивка — это чтение журналов, поэтому её можно делать для всей
истории при установке.

Человек подтверждает кандидатов, сливает и делит их. Молча задача не собирается.

Отклонено:

| вариант | почему нет |
| --- | --- |
| сшивать моделью по смыслу | всю историю пришлось бы читать моделью: ≈460 тысяч токенов на одну месячную беседу, а бесед сотни |
| сшивать по ключевым словам | на первой переписи ключевые слова дали шум: тема задачи упоминается в инструкциях проекта, и под неё попали беседы других задач |

## Решение 3: Codex читается через app-server, замер — из файлов

В продукте сессии Codex читаются через `codex app-server` (`thread/list`, `thread/read`),
а не из `~/.codex/sessions`. Формат на диске меняется: в Codex есть миграция истории
(`codex migrate-rollouts`), и старые файлы сжимаются в `.jsonl.zst`. Опираться на файлы значит
сломаться на следующем обновлении.

Этап «Сшивка бесед» — замер, а не продукт. Он читает несжатые файлы `~/.codex/sessions`
напрямую и называет это в отчёте. Сжатые файлы он считает, но не открывает. Так замер не тащит в
сборку зависимость от протокола app-server раньше, чем решено, нужна ли сшивка вообще.

## Решение 4 (следующий этап): карта строится моделью по запросу

Карта решений внутри задачи строится моделью только для задачи, которую человек открыл или
подтвердил. Дальше она достраивается по новым отрезкам и не перечитывает старое. Узлы карты
(развилка, ветка, риск, находка) доказываются цитатой так же, как факты слоя знаний (ADR 0048):
цитату находит программа, а без цитаты узла нет.

## Решение 5 (следующий этап): настоящие беседы остаются вне репозитория

Разбор настоящих бесед владельца содержит их реплики. Поэтому он хранится вне репозитория, а в
репозиторий попадают только числа и псевдонимы (`.claude/rules/00-core.md`). Задача первого
разбора — `quarry`, её беседа — `quarry-ledger`.

## Цена

- **Вторая платформа становится обязательной, даже для владельца, который работает в одной.**
  У разобранной задачи около 23 бесед существуют только как копии в хранилище Codex. Сшивка без
  Codex теряет первые полтора месяца задачи.
- **Источники исчезают.** Claude Code удаляет свои журналы примерно через месяц. Беседа, которую
  Crosskit не прочитал вовремя и которую никто не скопировал, для сшивки потеряна. Хранит ли
  Crosskit достаточно, чтобы сшивать без исходного файла, — вопрос следующего этапа.
- **Признаки зависят от чужих форматов.** Признак «файл-эстафета» требует знать, какие файлы
  беседа писала. У Claude Code это касания (ADR 0041), у Codex — патчи `apply_patch` и команды
  оболочки. Команды оболочки дают пути неточно, и замер должен показать, насколько.
- **Без разметки владельца точность неизвестна.** Замер показывает группы и признаки, которые их
  связали. Сколько из этого верно, скажет только поштучная разметка владельца.

## Замер 29 октября 2026: сшивка на машине владельца

```
CROSSKIT_STITCH_HOME=$HOME CROSSKIT_STITCH_SEED=<id беседы quarry-ledger> \
CROSSKIT_STITCH_LIST=<файл вне репозитория> \
  cargo test --release --offline --features task-stitching-measurement \
  --lib task_stitching:: -- --ignored --nocapture
```

Замер прочитал весь домашний каталог за 3 с, при этом машина была загружена (`vm.loadavg` 12,7).
Базу он не открывал, модель не вызывал, в репозиторий ничего не писал. Числа настоящие, названия
бесед в отчёт не попадают.

**Что прочитано.** 124 беседы:
- 44 оригинала Claude Code;
- 75 копий бесед Claude Code в хранилище Codex. Ещё 4 копии выброшены, потому что их оригинал
  лежит рядом;
- 5 собственных бесед Codex.

Служебных сессий 37: 20 исполнителей и 17 ревьюеров команд. Беседами они не считаются.

**Как правило менялось по ходу замера.** Затравка — беседа `quarry-ledger`. Каждая строка
таблицы — поправка, сделанная после того, как список связей показал её причину.

| правило | задача затравки, бесед | что было не так |
| --- | ---: | --- |
| признаки как в решении 2, без ограничений | 60, в 4 каталогах | долгоживущая локальная ветка связала 66 пар, манифест и README другого проекта — 42 и 35 пар |
| файл или ветку делят не больше 4 бесед, иначе это общий журнал | 22 | осталась цепочка через файлы кода и через беседу-замер, которая перечисляет десятки чужих бесед |
| эстафета и упоминание считаются только в начале беседы | 11 | файл кода, который одна беседа написала, а другая прочитала, ещё работал как эстафета |
| эстафета — только документ (`.md`, `.txt`, `.rst`); беседа, которая называет больше двух других, — обзор | **5**, ещё 4 через соседство | — |

Кривая при последнем правиле: без предела задача затравки — 6 бесед, при пределах 10, 6, 4, 3 и
2 — 6, 6, 5, 5 и 5. Если искать продолжение во всей беседе, а не в начале, при пределе 4 выходит
10.

**Точность.** По оценке разработчика все 5 бесед на сильных признаках относятся к задаче
`quarry`. Владелец это ещё не подтвердил. Четыре беседы, добавленные одним соседством, — открытый
вопрос: их нужно разметить.

**Разметка.** Замер выписывает в список вне репозитория все беседы рабочих каталогов задачи, а не
только найденные: у `quarry` их 40, из них сшивка взяла 5 по сильным признакам и 4 по соседству.
Владелец отмечает каждую «да» или «нет». Следующий прогон читает отметки из того же файла,
сохраняет их и печатает в разделе «З» верные, неверные и пропущенные беседы — отдельно для
оригиналов и для копий. Так точность и полнота считаются по разметке, а не по оценке разработчика.

**Полнота низкая, и её главная причина — копии.** Перепись насчитала у задачи около 35 бесед,
сшивка нашла 9. Почти все пропущенные — копии в Codex. У копии нет вызовов инструментов, поэтому
не видно, какие файлы она писала. У неё нет имени, поэтому её нельзя назвать. А время копии — это
момент импорта: десятки копий начинаются в одну и ту же секунду. У 75 бесед из 124 сшивке остаётся
только текст реплик.

**Что это значит для продукта.**
1. Сшивать нужно не исходные файлы, а то, что Crosskit уже прочитал и сохранил. Claude Code удаляет
   журналы примерно через месяц. Беседа, которую Crosskit прочитал вовремя, сохраняет вызовы
   инструментов, имя и настоящее время, а копия в Codex их теряет.
2. Предел общего журнала (4), поиск продолжения в начале беседы, эстафета только через документы
   и правило обзора остаются правилами этапа, а не продукта. Они подобраны на одной задаче. Перед
   продуктом их нужно проверить разметкой владельца хотя бы ещё на одной задаче.
3. Задача, центральный документ которой читает много бесед, по правилу общего журнала теряет этот
   документ как признак. На этой задаче такое не проверено. Если разметка покажет потерю, пределу
   нужна поправка: общий журнал определяется в пределах проекта, а не всей машины.
