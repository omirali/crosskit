# ADR 0026: исключения знают дерево, а не список экосистем

Статус: принято 2026-09-24 (Этап 20)

## Контекст

Первый живой прогон на настоящем дереве владельца дал запрос `product`, у которого **семь
результатов из десяти** пришли из `.venv/.../site-packages`. Очередь на анализ при этом
заполнялась файлами чужих пакетов — это уже не шум в выдаче, а счёт за модель.

`BUILT_IN_EXCLUDES` знал `.git`, `node_modules`, `target`, `.env`, `*.key` и `Library/Caches`.
Про питон, го, руби, iOS и кэши сборки он не знал ничего.

Очевидный ход — дописать имена — отвергнут до измерения: список имён отстаёт всегда. Он знает
только те инструменты, которые существовали на момент его написания, а каждый новый приходит
со своим каталогом, о котором никто не предупредит.

## Измерение: дерево владельца как есть

480 246 файлов, 26 git-репозиториев. Мерили настоящим обходчиком под настоящей политикой
(`what_the_exclusions_still_admit_on_a_real_tree`), без записи в базу.

| | файлов | ГБ |
| --- | ---: | ---: |
| всего на дереве | 480 246 | |
| **пропускала прежняя политика** | **200 813** | **5.42** |

Из чего состоял этот шум:

| | файлов | ГБ |
| --- | ---: | ---: |
| `.pnpm-store` | 86 701 | 1.06 |
| `site-packages` | 43 485 | 1.47 |
| `.venv` | 42 833 | 1.48 |
| `vendor` | 35 942 | 0.36 |
| `__pycache__` | 12 453 | 0.18 |

## Решение: сначала признак, потом имя

**Признак.** Каталог исключается целиком, если он несёт маркер, который оставил сделавший
его инструмент:

- `CACHEDIR.TAG` — общепринятый стандарт тегирования каталогов-кэшей; его пишут cargo, ruff,
  mypy, pytest;
- `pyvenv.cfg` — маркер корня питоновского окружения, который пишет стандартная библиотека,
  создающая это окружение, и больше он не встречается нигде.

На дереве владельца эти два имени пометили **15 каталогов: 43 760 файлов, 1.55 ГБ** — то есть
**все** питоновские окружения целиком, ровно ту причину, по которой выдача была засорена. При
этом слово «python» не появляется ни в одном правиле. Правило не устаревает: новый инструмент,
который пишет `CACHEDIR.TAG`, накрывается им без единой строки кода.

Маркер спрашивается одним `lstat` относительно уже открытого каталога — без листинга, без
сборки пути, без перехода по символической ссылке. Маркер, оказавшийся каталогом или ссылкой,
не считается маркером.

**Имя.** Только там, где признака нет, и только то, что **посчитано на настоящем дереве**:

| правило | файлов | ГБ | почему признак не покрывает |
| --- | ---: | ---: | --- |
| `**/.pnpm-store/**` | 86 701 | 1.06 | стоит рядом с `node_modules`, а не внутри |
| `**/vendor/**` | 35 918 | 0.36 | коммитится намеренно, поэтому и `.gitignore` мимо |
| `**/__pycache__/**` | 12 453 (2 309 вне маркеров) | 0.18 | лежит рядом с исходником, а не под корнем окружения |

**Не добавлены**, потому что на дереве их нет ни одного файла: `.tox`, `Pods`, `.terraform`,
`Carthage`, `DerivedData`, `bower_components`, `.gradle`. Имя, обоснованное тем, что оно
«бывает», — это тот же отстающий список, только написанный заранее.

| | файлов | ГБ | обход |
| --- | ---: | ---: | ---: |
| было | 200 813 | 5.42 | 8.85 с |

Остаток — исходный код: `.php`, `.yaml`, `.py`, `.js`, `.vue`, `.md`, `.ts`, `.go`. Оставшиеся
гигабайты почти целиком картинки и бинарники, которые и так публикуются метаданными.

## `.gitignore`: измерен и отклонён

Это сильнейший сигнал «сгенерировано, не моё», и он поддерживается самим проектом. Мерили
настоящей семантикой git (`git check-ignore --stdin -z --no-index`, по каждому репозиторию).

| | файлов | ГБ |
| --- | ---: | ---: |
| `.gitignore` сам по себе | 124 808 (62.2 %) | 3.40 |
| признак + имена | 168 688 (84.0 %) | 2.95 |
| **что `.gitignore` добавил бы сверх них** | **4 232 (2.1 %)** | 1.07 |
| **что признак + имена ловят, а он — нет** | **48 112 (24.0 %)** | 0.63 |

`.gitignore` **не заменяет** принятые правила: он пропускает 24 % того, что они ловят, потому
что `vendor` и содержимое окружений часто коммитят намеренно. Сверх них он добавляет 2.1 %
файлов — и это несколько каталогов с ассетами. Цена — полная семантика gitignore с
вложенностью, отрицаниями и приоритетом файлов по уровням. За 2.1 % файлов эта цена не берётся.

Решение отложено владельцу; здесь записаны числа, на которых оно принимается.

## Что случилось с путями, которые уже проиндексированы

Проверено измерением, и исходная посылка оказалась неверна наполовину.

**Поиск уже следует текущей политике.** Путь, ставший исключённым, перестаёт отвечать сразу
после ближайшего прохода — у `SearchResults` для этого есть именованный счётчик
`hidden_by_policy`, и совпадения по скрытым путям считаются, но не называются. Перестроение
для этого не нужно и не нужно было.

**Документы при этом остаются в файле индекса** до тех пор, пока файл не будет перечитан.
Убрать их на месте — выполнимо: `SearchIndexWriter::publish(files, [])` заменяет все документы
названных файлов пустотой, и это ровно то, что делает проход для файла, чья новая текущая
версия не держит текста. Закреплено тестом
`a_file_whose_text_was_deleted_stops_answering_after_one_ordinary_pass`: документы уходят за
один обычный проход, без перестроения, и обе половины остаются «в ногу» — а это и есть условие
того, что следующий проход не решит, будто индекс отстал, и не перепишет весь корпус.

**Чего политика не касается — очередь на анализ.** `claim_insight_jobs` отбирает задания по
состоянию и только по нему; задание, поставленное до исключения, будет выполнено и оплачено.
Это и есть та часть жалобы, которая про деньги, и она остаётся открытой.

## Смежная находка того же класса

Правило `required` требовало непустого текста **после `trim`**, и применялось к тексту чанка.
Из-за этого файл с пробельным блоком длиннее чанка отказывался целиком: документ с широким
пропуском посередине не индексировался вообще. Пробел — это содержимое: он занимает байты и
смещения. Текст чанка теперь держится более слабого правила — пустым он быть не может,
пробельным может.

Файл, в котором текста нет нигде, публикуется с нулём чанков — так всегда вёл себя пустой
файл. Публикация версии здесь не бухгалтерия: именно она снимает с файла, у которого стёрли
текст, статус текущего на той версии, где текст ещё был, и тем уводит его документы из индекса.
Пропуск файла оставил бы их отвечать.
