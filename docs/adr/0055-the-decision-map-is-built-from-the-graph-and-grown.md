# ADR 0055: карта решений строится по графу и дальше достраивается

Статус: принято 2026-10-29 (первая версия в продукте), ждёт приёмки владельца. Схема графа не
меняется. Номер машинного ответа не меняется (2): `tasks map --json` — новый объект.

## Контекст

Замер ADR 0054 показал три вещи.
- Haiku выдаёт предложения агента за выбор владельца.
- Короткая реплика владельца, поворачивающая работу, тонет рядом с длинными предложениями агента.
- Цитата доказывает 62–95 % узлов.

Владелец одобрил прогон на полном чате и попросил двигаться к продукту. Поэтому карта сразу вошла
в продукт, а её первый запуск стал проверкой.

## Решения

1. **Команда `crosskit tasks map <задача> [--build] [--only <беседа>] [--json]`.** Без `--build`
   она показывает построенное и модель не зовёт. С `--build` спрашивает только о репликах, которых
   карта ещё не покрывает.
2. **Реплики берутся из графа** (`speech_of`): куски собираются в реплики по длинам
   (`exact_replies_behind`), копии одной сессии схлопываются (`one_per_session`). Пока работает
   служба, реплики отдаёт она по сокету (`task-speech`). Модель спрашивает CLI, а не служба:
   построение занимает минуты.
3. **Узел без доказанной цитаты отбрасывается и считается** (`domain::decision_map::proved`, то же
   правило, что у фактов ADR 0048). Развилка без единой доказанной ветки — не развилка.
4. **Карта хранится по беседам** в `maps-<контекст>/<сессия>.json` рядом с графом, по той же
   причине, что и книга задач (ADR 0053). Каждая карта помнит последнюю покрытую реплику и номер
   вопроса. Карта, построенная другой версией вопроса, строится заново: два вопроса — это не одна
   карта.
5. **Вопрос v2** (`decision-map-v2`):
   - реплики владельца названы местом, где принимаются решения;
   - каждая такая реплика проверяется как развилка;
   - `chosen` ставится только по словам владельца;
   - риски ищутся и в длинных отчётах агента;
   - реплика длиннее 20 КБ обрезается с пометкой.
6. **Модель по умолчанию — `sonnet`**, если `[analysis.claude-code] model` не задан. Строит
   только движок `claude-code`. Движок держит разрешение контекста `send_content_outside` как
   значение, поэтому без разрешения его нельзя создать.

## Первый запуск: полный `quarry-ledger` (373 реплики, Sonnet)

| | |
| --- | --- |
| окон и вызовов | 10 |
| время | около 25 мин |
| цена по счётчику `claude` | 2,82 $ лимита |
| развилок / рисков (в задаче + вне её) | 22 / 33 + 2 |
| узлов доказано / отброшено | 99 / 42 (70 %) |

Сравнение с ручной разметкой той же беседы (раздел 10 концепции: ≈35 развилок и ≈68 рисков после
сведения):

- **Исправлено против замера.** Развилка «сначала данные, потом интерфейс», которую замер
  пропускал, найдена. Ни одно предложение агента не выдано за выбор владельца: где владелец
  молчал, стоит `ᵃ` или `?`.
- **Найдено верно:** пересборка дампов на свежих данных, форма без AI, обязательный договор,
  юридический адрес (без ответа), работа с двух сторон, не трогать админку, миграция даты НДС,
  один MR, предел 25 МБ. Находка про сломанный ETL правильно ушла в полосу «вне задачи».
- **Пропущено главное из поздней части:**
  - актуализация прода скриптами из пода без MR;
  - релиз без env;
  - прод-секреты, записанные открытым текстом в файл репозитория.

  Это самые дорогие решения беседы. Развилок в карте вдвое меньше, рисков — тоже.
- **Ложные узлы есть, и цитата их не ловит:**
  - модель приняла границу окна за конец беседы («реплика 61 последняя — результат не показан»);
  - модель написала риск о собственном режиме разметки.

  Цитаты у обоих настоящие: слова в реплике есть, вывод из них — нет.

## Что дальше (вопрос v3)

1. **Окно знает, что оно окно.** Вопрос называет первую и последнюю реплику окна и говорит, что
   беседа продолжается, чтобы граница окна не читалась как конец работы.
2. **Обязательный перечень критичного.** Отдельно спросить о правках прода, секретах и данных:
   были ли они в окне и чем закончились. Это тот класс, который пропущен, и он дороже всего.
3. **Узел о самой разметке отбрасывается программой.** Риск, который говорит о вопросе, а не о
   беседе, — признак, по которому узел отбрасывается.
4. **Развилка, у которой осталась только отклонённая ветка, читается как «ничего не выбрано».**
   Выбранную ветку проверка отбросила, потому что её цитату не нашла. Такую развилку нужно либо
   показывать с пометкой «выбор не доказан», либо отбрасывать, как развилку без веток. Решить
   по разметке владельца.
5. **Мерить по ручной разметке.** У `quarry-ledger` есть ручная карта. Следующая версия вопроса
   сравнивается с ней числами: найдено, пропущено, лишнее.
