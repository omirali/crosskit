# ADR 0027: одно «сюда мы не смотрим», и очередь, которая спрашивает

Статус: принято 2026-09-24 (Этап 21)

## 1. Пропуск по маркеру хоронил то, что лежит на диске

Владелец прогнал сверку после того, как заработали маркеры этапа 20, и получил
`Locations marked missing: 727`. Ничего не удалялось.

Два механизма разошлись:

- сверка щадит путь, только если **политика** называет его `Exclude` (правило этапа 2B:
  политика прячет, но не хоронит);
- каталог с маркером пропускался на уровне **обхода**, и политика про его содержимое
  `Exclude` не говорила никогда.

Молчание обхода о каталоге, в который он намеренно не вошёл, прочиталось как
доказательство отсутствия. Факт ложный и необратимый: `present` возвращается только
наблюдением, а весь смысл маркера в том, что наблюдения больше не будет.

**Решение — не второй механизм, а один.** Найденный маркер превращается в правило
`Exclude` на это поддерево на время прогона (`RuleOrigin::GeneratedDirectory`), сверка
добавляет эти правила к своей политике перед тем, как что-либо решать о путях, которых не
видела, и `is_visible` начинает работать сам собой. Сущности «пропущено, но не исключено»
больше нет.

### Аудит класса: каждое место, где обход что-то пропускает

Выписано целиком и проверено, а не выведено рассуждением.

| место | что пропускает | статус |
| --- | --- | --- |
| корень не допущен политикой | всё дерево | **защищено**: правило корня покрывает и потомков, retire не происходит (проверено) |
| маркер в каталоге | поддерево | **защищено** этой правкой (было сломано) |
| `admit` → `Exclude`, каталог | поддерево | **защищено** предикатом видимости |
| `visit_entry` → `Exclude`, файл | файл | **защищено** предикатом видимости |
| каталог не читается | содержимое каталога | **прогон незавершён** (`FailedPaths`, проверено) |
| имя не в UTF-8 | запись | **прогон незавершён** (`UnrepresentableNames`) |
| путь не собирается в нормализованный | запись | **прогон незавершён** (`FailedPaths`) |
| `lstat` записи не удался | запись | **прогон незавершён** (`FailedPaths`) |
| дочерний каталог не открылся | поддерево | **прогон незавершён** (`FailedPaths`) |
| файл изменился во время чтения | файл | **прогон незавершён** (`UnstableSources`) |

Незавершённый прогон не снимает статусы вовсе — `abandon_reconcile_run`, — поэтому шесть
нижних строк хоронить не могут по построению. Симлинки, спецфайлы, двоичные файлы, файлы
сверх предела и файлы без текста в этом классе не состоят: они публикуются, просто не
содержимым.

### Что делать с уже записанными ложными `missing`

Обычная сверка их **не лечит**, и это записано в README прямо: каталог теперь правильно не
обходится, а `present` возвращается только наблюдением. В выдаче они не всплывают — поиск
отбрасывает `missing`, — но история говорит неправду. Лечится снятием маркера на один
проход либо переиндексацией контекста.

## 2. Очередь теперь спрашивает политику

`claim_insight_jobs` отбирал задания по состоянию и только по нему. Задание, поставленное
до исключения пути, выполнялось и оплачивалось.

**Измерено на дереве владельца.** Очередь, наполненная до того, как исключения узнали
машину, против политики, которая действует сейчас:

| | заданий | текста |
| --- | ---: | ---: |
| в очереди было бы | 177 800 | 1.75 ГБ |
| политика всё ещё просит | 25 952 | 0.38 ГБ |
| **отсекается** | **151 848 (85.4 %)** | **1.37 ГБ** |

Задание существует на каждую опубликованную ревизию, то есть на файл, прочитанный как
текст в пределах лимита; классификация — как у самого обзора (NUL → двоичный, невалидный
UTF-8 → не текст), по первым 64 КиБ.

**Политика спрашивается при захвате.** Захваченное задание несёт пути, на которых его файл
ещё присутствует, и вопрос задаётся тем же предикатом, которым поиск решает, можно ли
показать путь: очередь и выдача обязаны отвечать одинаково. Ревизия, файла которой нет ни
на одном присутствующем пути, отвечает «нет» — платить за описание того, что никто не может
открыть, это та же трата другим путём.

**Исход — своё терминальное состояние.** `skipped`: не ошибка и не «мертво». За `dead`
стоит работа, которую пробовали, пока не кончились попытки; за `skipped` — вопрос, который
отозвали, ни одной попытки и ни одного вызова модели.

**Возврат: по ближайшему наблюдению, а не «терминально навсегда».** `persist_insight_job`
намеренно никогда не сбрасывает состояние существующего задания — оно принадлежит рабочему,
который им владеет. `skipped` — единственное исключение, и оно не ослабляет правило: за ним
не стоит ни работы, ни результата, ни потраченного, а функция, которая его сбрасывает,
выполняется только потому, что проход опубликовал ревизию снова, — а это происходит только
для файла, который политика допускает. То есть условие, отозвавшее задание, и есть то самое
условие, которое наблюдалось обратившимся. Альтернатива («терминально навсегда») теряет
анализ файла, который вернулся под индексацию и с тех пор не менялся, — а таких после любой
правки политики ровно столько, сколько она вернула.

Правило записано **один раз** и применяется обоими путями записи — одиночным (backfill
миграции) и пакетным (проход). Первая версия правки применила его только к одиночному, и
тест на возврат это поймал.

## 3. Устаревший текст: остановлено на границе

Этап 20 закрыл пустой файл и файл из пробелов. Двоичный, не-UTF-8 и файл сверх предела
по-прежнему идут через `SourceCommit::metadata_only`. Проверено на всех трёх причинах:
после того как файл стал двоичным, перестал быть UTF-8 или перерос предел, поиск
**по-прежнему отвечает его старым текстом**.

Причина одна: `metadata_only` не публикует версию, поэтому граф остаётся текущим на той
версии, где текст ещё был, и её чанки по-прежнему считаются тем, что индекс обязан держать.

**Почему механизм этапа 20 сюда не переносится.** Версия опознаётся хешем содержимого:

| причина | файлов на дереве | байт | можно ли опубликовать версию |
| --- | ---: | ---: | --- |
| двоичный | 6 150 | 1.44 ГБ | да, но дочитав файл до конца ради хеша |
| не UTF-8 | 7 | ~0 | да, тем же способом |
| сверх предела | 12 | 0.64 ГБ | **нет**: не открывать его — и есть смысл лимита |

Сейчас обзор останавливается на первом NUL, то есть читает килобайты. Дочитывание стоило бы
**+1.44 ГБ чтения на каждый проход** на этом дереве — и завело бы задание на анализ для
каждого двоичного файла, то есть вернуло бы другим путём ровно ту трату, которую убрал
пункт 2.

**Удалить документы напрямую тоже нельзя.** `publish(files, [])` убирает документы файла на
месте, без перестроения. Но `CURRENT_CHUNK_COUNT` продолжает считать чанки старой версии,
поэтому `documents() != expected`, и каждый следующий проход решает, что индекс отстал, и
переписывает весь корпус — механизм этапа 19, измеренный и намеренный.

**Механизм, который я считаю правильным, и почему он за границей.** Не публиковать версию, а
записать сам отказ: metadata-only коммит несёт наблюдение без версии, продвижение текущего
состояния снимает по нему ребро `CURRENT_VERSION`, а проход убирает документы файла тем же
`publish(files, [])`. Тогда счёт сходится сам, перестроение не нужно, лишнего чтения нет,
хеш не нужен, и это работает для всех трёх причин, включая файл сверх предела — отказ по
размеру известен, не открывая файл.

Цена: сегодня `FileObservation` **всегда** называет `FileVersion`, и на этой паре построен
`ObservationOrder` — машинерия, которая решает, новее ли кандидат текущего, и не даёт
опоздавшему повтору откатить состояние. Наблюдение без версии меняет инвариант доказательств
и порядок текущего состояния, то есть измеренную почву этапов 2 и 3. Это за границей этапа,
поэтому здесь остановлено.

**Что показывать вместо тишины — рекомендация.** Показывать, но помечать. Текст действительно
был в последней ревизии, которая его держала; человек, который ищет то, что сам написал,
хочет найти, где это было, даже если файл с тех пор переписан сборкой. У поиска уже есть
словарь для таких пометок — результат несёт `[present]`, а для скрытого политикой есть
счётчик. Третья пометка честнее и дешевле, чем молчание: спрятать стоит того же самого — граф
всё равно должен знать, что содержимое больше не индексируется, — и при этом теряет сведения.
Решение за владельцем; предпосылка у обоих вариантов одна и та же.
