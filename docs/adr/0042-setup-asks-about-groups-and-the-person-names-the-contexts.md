# ADR 0042: setup спрашивает о группах, а контексты называет человек

Статус: принято 2026-09-30 (Этап 39). Меняет ADR 0019, решение 2; ADR 0020, решение 2, не
меняется.

## Контекст

`setup` этапа 14 предлагал контексты по хосту remote и писал черновик по `--yes` или по «да».
На машине владельца это дало пять контекстов там, где он хотел два: под одним рабочим хостом
лежат три организации (этап 38, `docs/context-split-measurement.md`). Хост решает слишком
мало, а имя контекста, выведенное из хоста, — это догадка о том, как человек делит свою жизнь.

Этап 38 измерил, что решает: **группа в адресе `origin`** — первый сегмент пути. Папка
транскриптов Claude Code идёт за своим проектом у 73 бесед из 73, если имя папки вычислять
из пути проекта правилом самого инструмента и сверять с первым `cwd` внутри. Почта из reflog
одна на машину и репозиториев не различает, но называет домен владельца.

## Решение 1: из `.git/config` выходит хост и первая группа `origin` — больше ничего

ADR 0019 выпускал из `.git/config` только хост. Теперь выходит ещё **первый сегмент пути
`origin`**: у `git@git.example.org:acme/platform/app.git` это `acme`. Подгруппы, имя
репозитория, учётка из URL, порт и остальной путь не выходят.

Держится типом, как и раньше: `RemoteOwner` (`domain/git_remote/remote_owner.rs`) несёт
ровно хост и группу, `Origin` говорит, какой это случай — есть группа, хост без группы, путь
на машине, `origin` нет. Разбор текста из модуля не выходит. Читается только `origin`:
remote, из которого клонировали, — это то, откуда работа; второй remote — куда её ещё пушат.

Из глобального `~/.gitconfig` (и `~/.config/git/config`) берётся **домен** `[user] email`, и
только он: часть до `@` отбрасывается в домене (`domain/git_identity.rs`), до того как
значение кто-то держит. Reflog не открывается: этап 38 нашёл в нём один адрес на все 23
репозитория, и ничего сверх глобального файла он не сказал бы.

## Решение 2: единица вопроса — группа, а не проект

Спрашивается о группе: о вещах, которые держатся вместе, с причиной, почему.

| что | куда | причина |
| --- | --- | --- |
| проекты с одной группой `origin` на одном хосте | одна группа | одна группа `origin` |
| проект, у которого признака нет | группа из одного | «признака нет» и какого именно |
| репозиторий внутри проекта | с проектом, и это печатается | два контекста не покрывают один путь |
| папка транскриптов | с проектом, чья это папка | беседы этого проекта |
| папка без git | с группой, чьи беседы в ней работали | папка, где работали беседы группы |
| папка без git, где не работал никто | остаток | показывается до первого вопроса |

Ключ группы — хост и группа вместе: `acme` на двух разных хостах — две организации, пока не
доказано обратное. Группа, названная доменом почты владельца, или группа на хосте под этим
доменом, получает пометку **«похоже, ваша организация»**. Это пометка, а не решение: о ней
спрашивают так же, как о любой другой. По таблице этапа 38 16 внешних проектов владельца дали бы 9 групп; это подсчёт по
замеру, а не прогон `setup` на его машине — прогон делает владелец.

**Система не знает сторон.** Ни в домене, ни в выводе нет перечня вроде work/personal:
`ContextSide` этапа 38 остался в замере. Контекст — имя, которое ввёл человек; их может быть
два или пять.

## Решение 3: беседы идут за проектом, и папка проверяется, а не раскодируется

Имя папки `~/.claude/projects/<имя>` вычисляется из каталога формулой Claude Code
(`domain/transcript_folder.rs`, правило этапа 38) и никогда не читается обратно. Проверка —
первый `cwd` каждой беседы папки: он обязан кодироваться ровно в имя папки. Расхождение —
папка не раскладывается и печатается с тем `cwd`, где беседа началась. Тот же исход у папки
без бесед, у бесед без `cwd`, и у бесед, начатых в разных каталогах с одним именем.

Порядок: сначала то, что нашёл обход, — проект, папка без git, каталог над проектами
(«смешанная» папка), — и только потом временное место. Дерево, которое человек выбрал
обойти, его, где бы оно ни лежало; иначе проект в `/private/var/folders` стал бы мусором.

Папка транскриптов — обычный корень контекста: беседа распознаётся по `.jsonl` в любом
контексте (этап 32), папки двух проектов не пересекаются. В записываемый файл идут два
исключения `[index]` — `<~/.claude/projects>/*/*/subagents/**` и `…/tool-results/**`: это
транскрипты подагентов и сохранённый вывод инструментов, не беседа. Привязаны к месту в папке
транскриптов, а не к имени: каталог `tool-results` в проекте — чей-то исходник.

Этап 39b добавил третье: `<~/.claude/projects>/*/????????-????-????-????-????????????/**` —
весь каталог сессии, названный её UUID. На машине владельца там лежат `subagents/`,
`tool-results/`, `auto-mode-classifier-error.txt` (служебный дамп, повторяющий куски беседы;
владелец видел его в выдаче `search` рядом с беседой) и `custom-title.json`. Маска по форме
имени, а не «любой каталог»: рядом лежит `memory/` — заметки инструмента о проекте, они
остаются в индексе, — а сама беседа `<id>.jsonl` длиннее UUID.

## Решение 4: разговор, и молчание — не согласие

1. Сначала контексты: имена по одному, пустая строка — конец, минимум один. Имён по
   умолчанию нет.
2. Потом остаток: «всё, что останется без ответа, — в контекст …? [номер / n]». Если выбран,
   остаток пишется **явным списком корней**, а не правилом: завтрашняя папка рядом в него не
   попадёт без нового вопроса. С этапа 39b `n` значит не «никуда», а «по одной»: после групп
   каждая папка остатка спрашивается так же, как группа. Прогон владельца показал, зачем:
   семь папок остатка смешивали рабочее, личное и общее, ответ «всё или ничего» был `n`, и
   две явно рабочие папки остались вне контекстов.
3. Потом группы по одной: состав, причина, `[1] <имя> / … / [s]kip`, пустая строка — в
   остаток (или никуда, если остатка нет).
4. Потом файл целиком и `[y/N]`.

Закрытый ввод на любом вопросе — не «да»: ничего не пишется. `--yes` отказывается сразу, с
объяснением: контексты называет человек, догадки нет. Отказ на машине с объявленными
контекстами (ADR 0020, решение 2) не изменился; его текст называет, что делать, — отодвинуть
файл конфигурации и запустить снова.

Выход содержимого у всех новых контекстов выключен. При записи одна строка говорит, сколько
бесед в каждом контексте станут отправляемыми, если ему выход включить. В конце — итог по
контекстам и по всему, что осталось вне их, с причинами; Codex — одной строкой, сколько
сессий и что они вне контекстов.

## Что осталось за границей

* **Вырез поддерева** по-прежнему не выражается (ADR 0008): второй клон чужой организации
  внутри рабочего репозитория уходит с ним, и вопрос это печатает, но разделить не может.
* **Папки без git, где не работала ни одна беседа**, решаются только ответом на остаток.
* **Codex** не раскладывается: разборщика нет.
* **`contexts propose`** по-прежнему группирует по хосту — это черновик для вставки, и его
  правило этот этап не трогал.
* **Сверка с правдой владельца** (этап 38, раздел Е) не проведена и этим этапом не заменена:
  вопрос о группе — это не догадка, которую надо сверять, но проверка на его машине — его.

## Последствия

* `contexts propose` и `setup` стоят на одном обходе (`ContextProposalService::evidence`), но
  черновик делают разный.
* Правила этапа 38 — кодирование папки, `RemoteOwner`, домен почты — живут в продукте; замер
  под feature читает их оттуда и держит своё: стороны, правило сторон, reflog, эталон.
* Новый `setup` не создаёт отдельного контекста `chats`: беседы входят в контексты своих
  проектов.
