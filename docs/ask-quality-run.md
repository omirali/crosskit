# Проверка качества `ask`: процедура для владельца

Всё, что можно проверить без ключа, проверено тестами: сборка выдержек, бюджет, схема
ответа, кэш, отказ в запрещающем контексте, отказ без ключа, источники из собственного
списка. Качество ответов так проверить нельзя — нужен ключ и человек, который читает ответы.

Это процедура для одного прогона: десять вопросов по этому репозиторию, точная
последовательность команд и форма отчёта. Она воспроизводима: тот же репозиторий, те же
вопросы, тот же порядок.

## 1. Подготовка: отдельный контекст на этот репозиторий

Отдельный, чтобы прогон не трогал ваши рабочие контексты и чтобы разрешение на выход
содержимого касалось только этого дерева.

```bash
export CROSSKIT_DATA_DIR=/tmp/crosskit-ask-run
export CROSSKIT_CONFIG=$CROSSKIT_DATA_DIR/config.toml
mkdir -p "$CROSSKIT_DATA_DIR"

cat > "$CROSSKIT_CONFIG" <<'CONFIG'
[workspace.askrun]
include = ["/абсолютный/путь/к/crosskit"]
send_content_outside = true
CONFIG
```

`send_content_outside = true` — то самое разрешение. Без него команда откажется, и это
проверено тестом; здесь оно нужно, потому что прогон именно про то, что уходит наружу.

```bash
cargo build --release
./target/release/crosskit index init /абсолютный/путь/к/crosskit
./target/release/crosskit doctor          # индекс должен быть in step with the graph
```

## 2. Ключ

```bash
export ANTHROPIC_API_KEY=…
```

Модель и её усилие берутся из `[insight]`, как у воркера; по умолчанию это
`claude-haiku-4-5-20251001`. Если хотите прогнать на другой модели, допишите в конфиг:

```toml
[insight]
model = "claude-opus-5"
```

Каждая смена модели — это новый ключ кэша, то есть новый прогон, а не повтор старого.

## 3. Десять вопросов

Каждый вопрос про то, что в этом репозитории действительно записано, и у каждого есть файл,
где ответ живёт. «Попал» значит: среди названных источников есть ожидаемый файл.

```bash
ask() { ./target/release/crosskit --context askrun ask "$1"; }

ask "почему поисковый индекс лежит вне графа, а не в нём?"
ask "что происходит, если процесс индексации убить на середине прохода?"
ask "как Crosskit отличает новый файл, которому достался номер inode удалённого?"
ask "что делает команда index recover и что при этом теряется?"
ask "почему казахский язык не объявлен по умолчанию?"
ask "во сколько обходится мульти-стем: насколько растёт индекс?"
ask "что такое пропуск на выход содержимого и как он устроен?"
ask "сколько времени живёт аренда задания и сколько попыток даётся одному заданию?"
ask "почему миграция v12 переименовывает колонку вместо того, чтобы удалить её?"
ask "что делает watcher, если доставка событий файловой системы не подтвердилась?"
```

## 4. Форма отчёта

Одна строка на вопрос. `Sources sent` и `Sources used` печатает сама команда — переписывать
их не нужно, только перенести.

| # | вопрос (коротко) | sources sent | байт | названные источники | попал в ожидаемый файл | ответ верен | заметка |
| --- | --- | ---: | ---: | --- | --- | --- | --- |
| 1 | индекс вне графа | | | | да / нет | да / частично / нет | |
| 2 | убитый проход | | | | | | |
| 3 | переиспользование inode | | | | | | |
| 4 | index recover | | | | | | |
| 5 | казахский по умолчанию | | | | | | |
| 6 | цена мульти-стема | | | | | | |
| 7 | пропуск на выход | | | | | | |
| 8 | аренда и попытки | | | | | | |
| 9 | миграция v12 | | | | | | |
| 10 | watcher без событий | | | | | | |

Три колонки решают:

* **попал в ожидаемый файл** — назвала ли команда тот файл, где ответ действительно
  записан. Это про извлечение: если не попал, поиск принёс не то, и модель тут ни при чём.
* **ответ верен** — читается глазами по названным источникам. «Частично» — если ответ
  верен, но неполон или добавляет то, чего в выдержках не было.
* **заметка** — где именно рвётся: не хватило выдержек, выдержка обрезана посередине,
  вопрос понят иначе, ответ общий.

Внизу — три числа: сколько раз попал в ожидаемый файл, сколько ответов верны, сколько
частично.

## 5. Что с этим делать дальше

Число попаданий — это качество **извлечения**, а не модели: лексический поиск нашёл нужный
файл или не нашёл. Именно оно решает, нужны ли эмбеддинги, и ради него этот прогон
существует. Если попадания высоки, а ответы слабы — дело в выдержках или в вопросе к модели,
и чинится это дешевле эмбеддингов.

Повторный прогон того же вопроса ничего не стоит: ответ берётся из кэша
(`$CROSSKIT_DATA_DIR/ask-askrun/`). Чтобы спросить заново по-настоящему, удалите этот
каталог — он производный и ни на что больше не влияет.
