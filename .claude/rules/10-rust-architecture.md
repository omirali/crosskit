# Rust и Onion Architecture

## Направление зависимостей

- `domain` содержит предметные типы, инварианты и переходы состояний. Никаких `lbug`,
  файловой системы, CLI, HTTP, JSON-парсинга и конкретных AI-провайдеров.
- `application` описывает use case и порты (traits), оркестрирует domain и задаёт
  транзакционные границы. Он не знает Cypher и не форматирует терминал.
- `infrastructure` реализует порты: файловую систему, парсеры, LadybugDB, провайдеров
  и хранилища. Там не принимаются бизнес-решения.
- `presentation` разбирает аргументы, вызывает use case и форматирует результат. В ней
  нет доступа к базе, обхода диска или доменной логики.
- Зависимости направлены только внутрь: `presentation → application → domain`,
  `infrastructure → application/domain`. Не импортируй внешний слой во внутренний.

## Модули и API

- Для новой самостоятельной области создай предметный файл, например
  `src/domain/index_job.rs`, и экспортируй его из `src/domain/mod.rs`.
- Держи поля типов приватными, если внешний слой не обязан поддерживать их инварианты.
  Предпочитай конструкторы и методы с предметными именами.
- Не добавляй абстракцию только из-за одного вызова. Но повторяющуюся логику, формат или
  проверку храни в одном месте и покрывай тестом.
- Возвращай структурированные ошибки с контекстом. В production-коде не используй
  `unwrap()` для данных пользователя, файловой системы, сети или базы.

## Данные и безопасность

- Путь, содержимое файла и пользовательский текст — недоверенный ввод. Не собирай
  Cypher/команды через конкатенацию строк; используй параметры и типы.
- Не логируй секреты, полный текст приватных файлов или токены. Соблюдай политики из
  раздела 8 архитектурного документа.
